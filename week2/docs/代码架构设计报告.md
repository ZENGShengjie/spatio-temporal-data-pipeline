## 1. 设计目标

1. **可恢复**：每一步产物落盘，下一步只读不重算，从断点续跑。
2. **可观测**：每个 step 输出一份 `*_log.json`，记录耗时、行列、错误。
3. **可替换**：所有 I/O 路径由环境变量控制（`RAW_DIR`, `CLEANED_DIR`, `GRID_DIR`, `FEATURES_DIR`, `GRAPH_DIR`），本地 / EC2 / Docker 行为一致。
4. **可分批**：所有 step 默认按月/文件分批读取，适用 8 GiB 内存。
5. **可测试**：每个 step 都是纯函数 `clean_xxx() → df`，主函数只做 I/O 编排。

## 5. 代码设计原则

### 5.1 Step 脚本统一遵循 main + 子函数结构

```python
def clean_<source>():
    """I/O + 主流程编排"""
    ...

def _clean_<source>_df(df):
    """纯函数：df → df"""
    ...

if __name__ == "__main__":
    main()
```

### 5.2 配置与业务分离

| 类别 | 表示 |
|------|------|
| 路径 | 环境变量优先，默认值兜底 (`os.getenv("RAW_DIR", "/home/.../raw_nyc")`) |
| NYC 边界 | 模块顶部 `LON_MIN = -74.26` 等常量 |
| 算法参数 | KNN/CORR_THRESH 等放在 step4 模块顶部 |
| 调参文档 | docs/接口定义文档.md |

### 5.3 日志规范

每个 step 产生 `*_log.json`，结构：

```json
{
  "started":   "2026-07-07T08:14:13.625131",
  "finished":  "2026-07-07T08:15:47.989215",
  "n_rows":    19846072,
  "n_grids":   15875,
  "features":  ["grid_id", "datetime", ...],
  "errors":    []
}
```

### 5.4 错误处理

- **重启可恢复**：所有 step 检查产出文件已存在则跳过
- **失败显式**：try/except 包住大段，把异常写到 step_log.errors → 不静默吞错
- **早 fail-fast**：致命错误（缺 PBF、缺凭证）直接 `sys.exit(N)`

## 6. 数据流详细

### 6.1 raw_nyc → cleaned_nyc (step1)

```
input      processing                           output
taxi_*.pq  ① drop missing critical cols          taxi_nyc_clean.parquet
           ② bbox clip [-74.26, -73.70, 40.49, 40.92]
           ③ UTC normalize
           ④ trip duration 30~21600 s
           ⑤ avg speed ≤ 30 m/s
           ⑥ drop duplicates
           ⑦ (new) build (PULocationID, weekday, hour)
              bucket grid & linear interpolation → taxi_interpolated_buckets.parquet

weather    ① linear interp missing numeric         weather_clean.parquet
           ② dedup on datetime
           ③ mean by (weekday, hour)

poi        ① (osm_id, category) dedup              poi_clean.parquet
           ② bbox clip
           ③ (lon, lat) dedup

road       ① grid_id dedup                         road_density_clean.parquet
           ② NaN → 0 for road_len_*_m

ndvi       (step3b 单独处理)                       ndvi_clean.parquet
```

### 6.2 cleaned + grid → features (step3)

```
input                  join key                       output
weather_clean.parquet  (weekday, hour)  → mean        5 weather_*_norm
road_density_clean     grid_id                        road_length_m + tier
poi_clean              (lon,lat → grid_id)            poi_count_<cat>
ndvi_clean             grid_id                        ndvi_*
taxi_buckets           (PULocationID→grid_id,h,w)     taxi_pickup_count, dropoff
grid_500m.geojson      geometry                      centroid_lon/lat
```

### 6.3 features + grid → graph (step4)

```
input                transform                       output
grid_500m.geojson  centroid → (lon, lat)            15875 节点
features.parquet   groupby(grid_id).mean()           14 维聚合特征
                   min-max normalize → 10 维
spatial: haversine KNN=8          → 127000 edges
semantic: euclidean KNN=6         → 95250 edges
correlated: Pearson ≥ 0.7         → 8482 edges
                                                       HeteroData
```

## 7. 性能与扩展

### 7.1 当前性能 (t3.large, 8 GiB)

| Step | 输入大小 | 内存峰 | 耗时 | 备注 |
|------|---------|--------|------|------|
| step1_clean_new.py | 41M 行 × 12 文件 | ~3.5 GB | ~1 min | 已加 gc.collect() |
| step2_grid.py      | (无输入) | < 100 MB | < 1 s | |
| step3_features.py  | 20M+15.8K 行 | ~3 GB | ~8 s | 关键瓶颈：taxi pickup/dropoff 重算 |
| step4_graph.py     | 2.67M 行 | ~4 GB | ~1 min | corr 矩阵 ~16 GB float32 |

### 7.2 内存热点

1. `step4.build_flow_edges()` corrcoef matrix = `(N_GRIDS, 168)` shape，float32 ≈ 10 MiB；但 `corrcoef()` 内部是 (N,168) × (168,N)，输出 (N,N) = `15875^2 × 4 B = 1.0 GB`，**低于 8 GiB 上限但接近上限**，降阈到 0.5 时 KNN 更密就要小心。

2. `step3.build_taxi_flow_features()` 读取 `taxi_nyc_clean.parquet` (381 MB) 全列。已通过 `columns=[...]` 投影到 4 列降到 ~80 MB。

3. `step3.build_space_time_index()` 生成 `(15875 × 168 = 2,667,000)` 行笛卡尔积，float 列占 200 MB，仍可控。

### 7.3 横向扩展路径

- 数据并行：按 `month` 分 12 进程跑 step1，再 reduce
- 存储：Spark / Dask 替代 pandas（> 50 GiB 时）
- GPU：step3 / step4 上 NVIDIA T4 (g4dn.xlarge) 后，Pandas→cudf

## 8. 接口契约概览

详细见 `docs/接口定义文档.md`。一句话：

```
step_in → pandas.DataFrame → step_out
       │ (arrow parquet)
       ▼
cleaned_nyc/*.parquet
grid_nyc/*.parquet
features_nyc/*.parquet
graph_nyc/*.pt
```

每个 step **只读自己声明的输入、只写自己声明的输出**。
