## 3. 清洗层 (`step1_clean.py`) 评估

清洗日志 (`cleaned_nyc/cleaning_log.json`)：

| 数据源 | 输入行数 | 输出行数 | 保留率 | 主要清洗动作 |
|--------|---------|---------|--------|-------------|
| TaxiNYC | 41,169,720 | 19,846,072 | **48.2%** | 去缺失 → bbox 裁剪 → UTC → 30s-6h 时长过滤 → 速度 ≤30 m/s → 跨文件 dedup |
| POI | 1,673 | 1,673 | 100% | within-source dedup → coord dedup → bbox |
| Road | 15,875 | 15,875 | 100% | grid_id dedup + NaN→0 |
| Weather | 9,072 | 8,808 | 97.1% | datetime dedup → linear interpolation |
| Landsat | — | — | n/a | (NDVI 另由 step3b 处理) |

### 3.1 TaxiNYC 12 月数据保留率

```
input  = 41,169,720
output = 19,846,072
remove = 21,323,648 (51.8%)
```

主要清洗项（按顺序）：

1. 缺失 `pickup_datetime` / `dropoff_datetime` → drop
2. `pickup_longitude` ∈ `[-74.26, -73.70]` 且 `pickup_latitude` ∈ `[40.49, 40.92]` → drop 越界
3. `duration_s` ∈ `[30, 21600]` → drop 异常行程
4. 平均速度 ≤ 30 m/s（≈ 108 km/h） → drop 漂移点
5. `fare_amount` ≥ 0 + `passenger_count` ∈ [1, 8] → drop 异常
6. 跨 12 个月文件 dedup（精确行级去重）

> **注意：** NYC TLC 出货已不含原始 lat/lon，仅保留 `PULocationID` (1~263 区) 与 `DOLocationID`。`step1_clean.py` 已降级为基于 `LocationID` 的特征（`PULocationID`、`DOLocationID`），与原计划的 lat/lon 过滤有差异，详见 §8 已知问题。

### 3.2 POI 问题

当前 `poi_clean.parquet` 仅包含 **residential** 一类 (1,673 条)，food/shop/entertainment/office 四类 **未成功落格**：

- 原因：`extract_osm_v2.py` `osmium tags-filter` 已正确生成 5 个 .osm 子集，但 `extract_poi()` 当前只读取 `residential.osm`，其他 4 类因运行内存不足导致聚合被截断。
- 影响：下游 `step3_features.py` 的 `poi_total_count` 范围 [0, 103] 实际为 residential 计数。

## 5. 特征层 (`step3_features.py`) 评估

`features_nyc/nyc_features.parquet`：

| 指标 | 值 |
|------|----|
| 行数 | **2,667,000** (= 15,875 grid × 168 hour) |
| 列数 | **36** |
| 文件大小 | ~685 MB |
| 数据类型分布 | object:1 / datetime64:1 / float32:18 / float64:8 / int64:4 / int32:2 / int8:2 |

### 5.1 特征分组与 schema

```
1. 主键 (3)
   grid_id : str (nyc_gXXXX_YYYY)
   datetime: datetime64[ns]
   weekday : int64 (0~6)
   hour    : int64 (0~23)
   month   : int64

2. 时间编码 (8)
   hour_sin, hour_cos, weekday_sin, weekday_cos, month_sin, month_cos,
   is_weekend (int8), is_holiday (int8)

3. 空间距离 (6)
   dist_to_times_square, dist_to_central_park, dist_to_wall_street,
   dist_to_grand_central, dist_to_jfk_airport, dist_to_nearest_landmark,
   dist_to_city_center

4. POI (7)
   poi_food_count, poi_shopping_count, poi_entertainment_count,
   poi_office_count, poi_residential_count,
   poi_total_count (int32), poi_density_per_km2 (float32)
   ★ 当前只有 residential 类别非 0，见 §3.2

5. 路网 (3 + tier 4)
   road_length_m, road_segment_count, road_density_km_per_km2,
   road_len_tier_highway_m, road_len_tier_major_m, road_len_tier_minor_m, road_len_tier_local_m

6. 轨迹 (2)
   taxi_pickup_count, taxi_dropoff_count (int32)

7. 气象 (5, 0~1 归一化)
   weather_temp_norm, weather_humidity_norm, weather_pressure_norm,
   weather_wind_speed_norm, weather_clouds_norm

8. 卫星 (5)
   ndvi_mean, ndvi_max, ndvi_min, ndvi_count, is_water
```

### 5.2 关键数值分布

| 特征 | min | max | mean | 偏度 | 备注 |
|------|-----|-----|------|------|------|
| `taxi_pickup_count` | 0 | **15,863** | 7.44 | 极高 | **必须 log1p 处理** |
| `taxi_dropoff_count` | 0 | (同形态) | — | 极高 | 同上 |
| `poi_total_count` | 0 | 103 | 0.105 | 高 | residential alone |
| `road_density_km_per_km2` | 0 | 169.12 | 14.82 | 中 | 曼哈顿核心高 |
| `weather_temp_norm` | 0.463 | 0.644 | 0.547 | 极低 | 1 周样本量小 |
| `ndvi_mean` | (—) | (—) | (—) | 中 | 0~0.8 区间 |

### 5.3 时空对齐校验

```
grid_id      nunique  = 15,875  ✅
weekday      nunique  = 7       ✅
hour         nunique  = 24      ✅
(weekday,hour) ngroups = 168     ✅
总行数 = 15,875 × 7 × 24 = 2,667,000 ✅（笛卡尔积完整）
```

**关联性：** 全部空缺已用左侧 join 的零值填补（无全 NaN 行）。

## 6. 图层 (`step4_graph.py`) 评估

`graph_nyc/nyc_hetero_graph.pt` (PyTorch Geometric `HeteroData`)：

| 维度 | 类型 | 边类型 | 边数 |
|------|------|--------|------|
| 节点 `(15875, 10-d)` | `float32` (已 0~1 归一化) | — | — |
| 边 spatial   | undirected KNN | `(spatial, adjacent, spatial)` | **127,000** |
| 边 semantic  | undirected KNN | `(spatial, similar, spatial)`  | **95,250**  |
| 边 correlated | undirected | `(spatial, correlated, spatial)` | **8,482**  |

| 参数 | 值 | 说明 |
|------|----|------|
| `KNN_SPATIAL`  | 8 | haversine KNN，无自环 |
| `KNN_SEMANTIC` | 6 | euclidean KNN，基于归一化特征 |
| `CORR_THRESH`  | 0.7 | Pearson 相关系数阈值（流量合并 pickup+dropoff） |

### 6.1 节点特征

`build_node_features()` 将 `nyc_features.parquet` 按 grid_id 求 mean，并 0~1 归一化 14 个聚合维度（剔除 14 维归一化特征列，最终保留 `node_feature_dim=10`）。

> **注意：** 节点特征维度仍较小（10），下一步可把 `road_len_tier_*_m`、`weather_*_norm` 全部纳入节点特征。

### 6.2 边连通性

- 空间 / 语义边密度（无向，KNN=8/6）正常。
- 相关性边 (8,482) 只占 **0.27%**，与预期一致（高阈值 0.7 严格）。

## 8. 已知问题与改进建议

| # | 问题 | 影响 | 建议改进 |
|---|------|------|---------|
| 1 | POI 5 类中仅 residential 落格成功 | food/shop/entertainment/office 缺失 | 把 `extract_osm_v2.py` 的 4 个 POI 文件读取移到独立脚本，先 select 列再聚合 |
| 2 | TaxiNYC 输入无 lat/lon | 已按 PULocationID/DOLocationID 处理 | 改用 TLC zone shapefile 空间可视化 |
