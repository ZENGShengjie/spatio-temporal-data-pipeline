## 访问地址（变量化 — 每次动态变化）

EC2 实例的公网 IP 每次重启都可能变（分配 Elastic IP 后才固定）。本脚本**不写死 IP**，统一用占位符：

| 占位符 | 含义 | 本地默认值 | 生产示例 |
|--------|------|-----------|---------|
| `{{API_HOST}}` | FastAPI 服务地址 | `http://localhost:8000` | `http://3.238.87.116:8000` |
| `{{STREAMLIT_HOST}}` | Streamlit 界面地址 | `http://localhost:8501` | `http://3.238.87.116:8501` |

> **替换方式**：演示前用 `sed -i` 或编辑器批量替换，把 `{{API_HOST}}` 替换成当前 EC2 公网 IP 即可。
> 也可以设环境变量：
> ```bash
> export API_HOST="http://3.238.87.116:8000"
> export STREAMLIT_HOST="http://3.238.87.116:8501"
> ```
> Streamlit 端 `week6/app.py` 已经支持 `API_BASE` 环境变量覆盖默认值，无需改代码。

## 幕一：端到端 Pipeline（90 秒）

> **目标**：展示底层 Pipeline 的两种模式（batch + 模拟实时）

**操作 1：批量处理模式**

在终端标签页运行：
```bash
cd /home/ubuntu/amazon
python -m week6.pipeline
```

**预期输出**：
```
=== Week6 Pipeline Quick Demo ===
[Pipeline] batch(test) done in 1.8s, anomalies=4893/615936, events=1443, alerts=...
  alert breakdown: {'一般': ..., '重要': ..., '紧急': ...}
```

**演讲稿**：
> "这是底层 Pipeline 的快速演示。批量模式跑完整个测试集（600 步 × 1024 网格），耗时不到 2 秒。检测出 1443 个时空聚合异常事件，分布在三级预警里。Pipeline 内部封装的逻辑包括：数据加载 → 统计法打分 → 预测法打分 → 三路融合 → 异常判定 → 事件聚合 → 预警判定，全程无需任何手写业务逻辑。"

**操作 2：演示 Pipeline 模块化**

```bash
python -c "
from week6.pipeline import SpatiotemporalPipeline, WarningEngine
p = SpatiotemporalPipeline(mode='fast', use_cache=True)
res = p.run_batch(split='test')
print('flow shape:', res['flow'].shape)
print('scores keys:', list(res['scores'].keys()))
print('events[0]:', res['events'][0])
"
```

**演讲稿**：
> "Pipeline 完全模块化，所有算法复用 week5 的代码，没有任何重写。返回的结果是结构化字典：flow 是人流矩阵，scores 包含五路得分，events 是异常事件列表。"

**操作 3：模拟实时模式（滑动窗口）**

```bash
python -c "
from week6.pipeline import SpatiotemporalPipeline
import numpy as np
p = SpatiotemporalPipeline(mode='fast', use_cache=False)
p.init_realtime(warmup_steps=48)
for i in range(5):
    out = p.run_step()
    print(f't={out[\"t\"]} fused_mean={out[\"scores\"][\"fused\"]:.4f} '
          f'n_anom={out[\"anomaly_mask\"].sum()} alert={out[\"alert\"].level_name if out[\"alert\"] else None}')
"
```

**演讲稿**：
> "除了批量模式，Pipeline 还支持滑动窗口实时模式。冷启动 48 步预热（约 2 天数据），之后每输入一步数据，立即输出当前步的异常判定和预警。这模拟了真实生产环境数据流式接入的场景。"

**演讲稿**：

**操作 4：调用 `/api/anomaly/detect`（异常检测）**

```bash
curl -X POST {{API_HOST}}/api/anomaly/detect \
  -H "Content-Type: application/json" \
  -d '{"t": 3500, "mode": "fast"}' | python -c "
import json, sys
d = json.load(sys.stdin)
print(f't={d[\"t\"]} timestamp={d[\"timestamp\"]}')
print(f'n_anomaly={d[\"n_anomaly_cells\"]}/{d[\"n_total_cells\"]} rate={d[\"anomaly_rate\"]*100:.2f}%')
print(f'warning={d[\"warning_name\"]} (level {d[\"warning_level\"]})')
print(f'processing_ms={d[\"processing_ms\"]:.0f}ms')
"
```

**预期响应**：
```
t=3500 timestamp=2015-11-05T16:00
n_anomaly=87/1024 rate=8.50%
warning=重要 (level 2)
processing_ms=180ms
```

**演讲稿**：
> "异常检测接口接收时间步和模式（fast/structural），返回该时间步的完整检测结果：异常格点数、异常率、预警等级（一般/重要/紧急）、处理耗时。响应时间 180 毫秒，达到准实时水平。请求参数 mode 是关键 — fast 模式只用统计法 + 预测法（响应<1秒），structural 模式会懒加载 VAE/TAE 模型，专门针对连片异常。"

**操作 5：模式切换演示**

```bash
# 切到 structural 模式（懒加载深度学习模型）
time curl -X POST {{API_HOST}}/api/anomaly/detect \
  -H "Content-Type: application/json" \
  -d '{"t": 3500, "mode": "structural"}' > /dev/null
```

**演讲稿**：
> "第一次请求 structural 模式需要懒加载 VAE/TAE 模型，耗时约 3-5 秒。后续请求就跟 fast 模式一样快。生产环境通常默认 fast，需要深度分析时再切换。"

**操作 6：调用 `/api/anomaly/events`（事件查询）**

```bash
curl -X POST {{API_HOST}}/api/anomaly/events \
  -H "Content-Type: application/json" \
  -d '{"t_start": 3288, "t_end": 3500, "min_cells": 20}' | python -c "
import json, sys
d = json.load(sys.stdin)
print(f'total={d[\"total\"]}')
for e in d['events'][:3]:
    print(f'  id={e[\"event_id\"]} t=[{e[\"t_start\"]},{e[\"t_end\"]}] '
          f'duration={e[\"duration\"]} cells={e[\"n_cells\"]} '
          f'level={e[\"warning_level\"]}级-{e[\"level_name\"]}')
"
```

**演讲稿**：
> "事件查询接口支持时间范围、最少网格数、是否包含零散事件的灵活过滤。返回每个事件的完整元数据：起止时间、持续步数、影响范围、中心坐标、预警等级。这是时空聚合后的结构化输出。"

## 幕三：Streamlit 实时热力图 + 预警（90 秒）

**操作 1：进入 Tab 1 实时热力图**

1. 点击「**📊 实时热力图**」
2. 默认显示 t=3488 时刻
3. 下方 4 个指标卡：异常格点 / 异常率 / 预警等级 / 处理耗时

**操作 2：跳到早高峰**

1. 点「**早高峰 (~08:00)**」按钮
2. 异常率显著上升，预警等级升到二级或三级

**操作 3：跳到夜间低谷**

**演讲稿**：
> "凌晨 3 点，异常率回落到 1% 以下，预警消失，符合城市夜间的低活跃规律。"

| 环节 | 建议 |
|------|------|
| 分辨率 | 1920×1080，全屏浏览器 |
| 录制前 | 关闭通知、隐藏任务栏、关闭个人消息 |

## 常见应急

| 现象 | 应对 |

| 忘了讲什么 | 看小抄：本文件幕零~幕八 |
